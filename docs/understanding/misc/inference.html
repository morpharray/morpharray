How LLMs Generate Text:
Understanding the Inference Process

Ben Um • April 2026

Large language models don’t “think” in one magical step. They generate text through a very specific, repeatable mechanical process called inference. This process has two main phases: Prefill and Decode.

1. Prefill Phase – Building the Context

When you send a prompt, the model first processes the entire prompt in parallel. This is called the prefill phase.

During prefill, the model:

  • Converts every token in your prompt into embeddings
  • Runs them through all transformer layers
  • Computes and stores Key (K) and Value (V) vectors for every token in every layer
The result is the KV Cache — a large, passive collection of stored tensors that acts like a rich “instruction matrix” containing the model’s understanding of your prompt (instructions, context, facts, tone, constraints, etc.).

At the end of prefill, the model also produces a final hidden state for the last token in the prompt. This is the model’s internal summary of everything it has seen so far.

2. Decode Phase – Generating One Token at a Time

Once prefill is complete, the model switches to autoregressive generation — it generates tokens one by one.

Inside Each Decode Step:

  1. Take the current hidden state (on the first step, this comes from prefill; afterward, it comes from the previous step).
  2. Process the newest token
    The model computes a new Query (Q), Key (K), and Value (V) for this token.
    It appends the new K and V to the KV cache.
  3. Read from the KV Cache
    The new Query performs attention over the entire KV cache using two matrix operations:
    scores = Q_new × K_cache^T / √d_head
    attention_output = softmax(scores) × V_cache
    This is how the model “consults” all the stored understanding from the prompt and previous tokens.
  4. Update the hidden state
    The attention output flows through the feed-forward network (MLP) and other layers. After all layers, the model produces a new final hidden state (size = d_model, typically 4,000–12,000 dimensions).
  5. Project to Vocabulary (The Critical Step)
    The final hidden state is passed through a simple linear layer called the language model head:
logits = final_hidden_state × W_unembed^T

This single matrix multiplication produces a vector called logits, which has length vocab_size.

vocab_size is usually 32,000 to 128,000+.
This means the model outputs one score for every possible token it knows — creating a massive list of candidates for the next word.

6. Choose the Next Token

The logits are converted into probabilities (using softmax, often with temperature or top-p sampling). One token is then selected and fed back into the model as the next input. The process repeats.

Summary: The Full Picture

  • Prefill: Heavy parallel processing → builds the passive KV cache (instruction matrix) + initial hidden state.
  • Decode: Repeated loop:
    • Read from the KV cache via attention
    • Update the hidden state
    • Project from d_model to vocab_size → logits
    • Sample the next token

The KV cache is passive — it stores contextual information but does no computation itself. All the active work happens in the attention reads and transformer layers. The final projection to vocab_size is what turns the model’s rich internal representation into actual fluent text choices.

This mechanical process — not magic — is what allows today’s LLMs to produce coherent, context-aware output. Surface-level understanding emerges from the sophisticated interaction between the stored KV cache and the active computation at each step.
