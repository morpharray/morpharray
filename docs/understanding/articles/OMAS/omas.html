The Micro-CMAS Inside Every Token

How Large Language Models Run an Emergent Coordinated Multi-Agent System During Generation

by Ben Um (inspired conversation with Grok)

1. The Core Insight

During autoregressive generation, a transformer is not merely "predicting the next token." It is continuously running a dense, implicit micro Coordinated Multi-Agent System (micro-CMAS) at every single token step.

This micro-CMAS is the hidden counterpart to the explicit coordinated multi-agent systems we build with frameworks like LangGraph, CrewAI, or AutoGen.

2. Components of the Micro-CMAS

The Supervisor / Orchestrator

The current residual stream (hidden state) at each generation step acts as the central supervisor. It encodes the current "mode" or intent and projects it into queries (Q).

Specialist Sub-Agents

  • Attention heads & emergent circuits: Parallel sub-agents with specialized roles (induction heads for pattern matching, copy-suppression heads, task-vector maintainers, replacement routers, etc.).
  • Multi-layer hierarchy: Lower layers handle low-level pattern detection; higher layers compose behaviors.

The Mission Plan

The KV cache serves as the living Mission Plan — a shared, continuously updated record of the entire operation.

It contains the full history of instructions, role separations, constraints, partial computations, and contextualized token representations. Every sub-agent can consult any part of the Mission Plan at any time, but the supervisor decides which sections are relevant for the current token via content-based attention.

Routing & State Transitions

Attention (Q·K similarity + softmax) performs soft, continuous state transitions across the Mission Plan. No explicit if statements — just vector geometry routing the system from "search mode" → "replace mode" → "output payload mode" at token granularity.

3. Micro-CMAS vs. Macro-CMAS

Micro-CMAS (inside one model during generation):

  • Emergent, continuous, high-dimensional
  • Extremely efficient (one forward pass)
  • Maintains a dynamic Mission Plan and coordinates sub-agents automatically

Macro-CMAS (explicit coordinated systems):

  • Engineered, discrete, observable
  • A supervisor LLM + specialist agents + explicit shared state (often a vector store or message history)
  • The same fundamental pattern, just unfolded outside the transformer for reliability, debugging, and scale

The transformer has already invented hierarchical stateful coordination — complete with its own internal Mission Plan — in vector space. Modern agent frameworks are simply externalizing and making that pattern controllable.

4. Concrete Example: Search-and-Replace

When instructed to perform search-and-replace:

  • The Mission Plan holds the original instructions, the input text, and the replacement rule in contextualized form.
  • One sub-agent attends to the instruction section of the Mission Plan (task vector).
  • Another detects the search term via induction heads.
  • Copy-suppression prevents treating output as new instructions.
  • The supervisor smoothly transitions the system into replacement mode by consulting the appropriate parts of the Mission Plan.

All of this happens token-by-token without any explicit control flags.

5. Implications

  • Single-model prompting feels powerful because a full micro-CMAS — complete with its own dynamic Mission Plan — is already running inside it.
  • We still need macro-CMAS frameworks when we want determinism, debugging, tool integration, or multi-model collaboration.
  • Understanding generation as micro-CMAS unifies mechanistic interpretability with agent engineering.
